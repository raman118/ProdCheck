# Check catalog

Severity values: critical, high, medium, low, info. Every check is a pure function over a bounded snapshot and context. Each check must add tests and false-positive guidance before release.

| ID       | Severity                                       | Detection rule                                                                                                                                       | Fix template                                                                                                            | False-positive notes                                                                                                                   |
| -------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-001  | high; critical on `/admin`                     | AST-discovered exported Next route handler in `app/api` or `pages/api` has no auth marker in its file                                                | AUTH-GUARD: check the session/user before handler work                                                                  | Shared middleware and custom auth wrappers may be missed; comments can cause false negatives; health routes are exempt                 |
| SEC-002  | critical for known keys/env; high for entropy  | Detects common GitHub, Stripe, Supabase, and AWS key formats; secret-like assignments with Shannon entropy ≥4.2; committed `.env*` except examples   | SECRET-ROTATION: remove value, rotate credential, add key name to `.env.example`, ignore local env                      | Test credentials can look real; reports mask detected values; uncommon key formats may be missed                                       |
| SEC-003  | critical                                       | Flags service-role/private references in `"use client"` or client/public paths and secret-like `NEXT_PUBLIC_*` names                                 | SERVER-SECRET: move credential access into a server-only module and remove public prefix                                | Public anon keys are excluded; client classification and custom bundlers can be missed                                                 |
| SEC-004  | medium                                         | Finds `Access-Control-Allow-Origin: *`, `headers.set(..., "*")`, or `cors({ origin: "*" })`                                                          | CORS-ALLOWLIST: where the syntax is recognized, replace `*` with `APP_ORIGIN` (localhost fallback); patch must validate | Public static APIs may intentionally allow all origins; uncommon CORS syntax gets no automatic patch                                   |
| SEC-005  | medium                                         | Checks detected Next, middleware, hosting, and server config files for CSP, HSTS, and frame protection                                               | SECURITY-HEADERS: add CSP, HSTS, and X-Frame-Options through a new Next config or a plain default object                | Reverse proxies and hosting dashboards may set headers outside the repository; existing custom config shapes are skipped               |
| SEC-006  | high                                           | AST detects `eval`, `Function` constructors, and unsanitized `dangerouslySetInnerHTML`; line heuristic detects interpolated or concatenated SQL text | DANGEROUS-CODE: use fixed code paths, a reviewed HTML sanitizer, and parameterized SQL                                  | Sanitizer variable flow and multiline SQL are heuristic; trusted constants require review                                              |
| DATA-001 | high                                           | SQL `CREATE TABLE` in `supabase/migrations` has no corresponding `ENABLE ROW LEVEL SECURITY`                                                         | RLS-ENABLE: if `owner_id`, `user_id`, or `created_by` is declared, add RLS plus an authenticated owner policy           | Non-user-facing tables may be server-only; tables without a clear owner column get no automatic patch                                  |
| DATA-002 | critical for unconditional; high for ownerless | Policy has `USING (true)`, `WITH CHECK (true)`, or lacks `auth.uid()` outside a service-role-only policy                                             | RLS-OWNER: tie reads/writes to `auth.uid()` or an explicit role                                                         | Role-scoped service policies need review; policy parser is heuristic                                                                   |
| DATA-003 | medium                                         | Supabase `.from(...).eq/order/...` or SQL `WHERE` references a known schema column with no primary/unique/index declaration                          | DB-INDEX: add an index migration for the frequently queried column                                                      | Dynamic query construction, composite index order, and complex joins may be missed                                                     |
| DATA-004 | high; critical for unbounded DELETE            | Migration contains `DROP TABLE/COLUMN`, `DELETE FROM` without `WHERE`, or `ADD/SET NOT NULL` without a default/backfill                              | SAFE-MIGRATION: stage the change, backfill, and verify before enforcing                                                 | Intentional destructive migrations need review; SQL parsing is heuristic                                                               |
| REL-001  | high                                           | Public/auth-shaped route or route without visible auth has no route-local rate-limit marker                                                          | RATE-LIMIT: apply per-IP or per-account limiter before expensive work                                                   | Upstream/global middleware may be configured outside the file; health routes are exempt                                                |
| REL-002  | medium                                         | Route reads JSON/form data or `req.body` without a visible schema validator                                                                          | REQUEST-SCHEMA: validate input with Zod/Joi/Valibot before use                                                          | Validation in a called helper may be missed                                                                                            |
| REL-003  | medium                                         | `fetch`, Axios, or Supabase call lacks visible timeout or `try/catch`/`.catch()`                                                                     | EXTERNAL-CALL: add a deadline and handle the failure path                                                               | Shared wrappers may provide both; file-wide `try` can hide an uncovered call                                                           |
| REL-004  | low                                            | No health/healthz route path or Express-style health registration detected                                                                           | HEALTH-ROUTE: add a lightweight Next.js app-router or pages-router `/api/health` route                                  | Platform health checks may be external; unrecognized layouts get no automatic patch                                                    |
| OBS-001  | medium                                         | No pino/Winston-style structured logger and/or no Sentry/Bugsnag/Rollbar/Datadog marker                                                              | OBSERVABILITY: add structured logs and server-side error capture                                                        | Hosted platform logging may exist; custom providers may be missed                                                                      |
| QUA-001  | medium                                         | No `*.test.*`, `*.spec.*`, or `__tests__` file                                                                                                       | TEST-STARTER: add focused unit tests for business rules                                                                 | Small utilities may reasonably lack tests                                                                                              |
| QUA-002  | medium                                         | No GitHub Actions, GitLab, CircleCI, Azure, Bitbucket, or Jenkins config                                                                             | CI-WORKFLOW: run typecheck, lint, tests, and build on pushes                                                            | External CI may be used                                                                                                                |
| QUA-003  | high                                           | Exact npm package/version has an OSV advisory; offline lookup uses a checked-in matching fixture                                                     | DEPENDENCY-UPGRADE: upgrade to the advisory's fixed version and refresh the lockfile                                    | Advisory reachability and affected ranges need context; offline fixture is intentionally small                                         |
| QUA-004  | medium                                         | No supported lockfile, or manifest dependency is not an exact semver pin                                                                             | PIN-DEPENDENCY: use the exact parsed lockfile version when available                                                    | Missing lockfile and unsupported lock formats need package-manager regeneration; workspace/file/link/catalog protocols are intentional |

Patch generation and validation rules live with M4; undocumented checks cannot ship.

M2 implementation is intentionally static and conservative. The checks inspect repository text and AST only; they never import or execute scanned files. Their signals are explainable but do not replace a security review.

M3 DATA/OBS/QUA checks use bounded migration, manifest, and lockfile parsing. OSV requests happen in a separate bounded adapter; checks consume its results as context and remain pure.
